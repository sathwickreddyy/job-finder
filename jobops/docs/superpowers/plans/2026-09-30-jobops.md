# JobOps Implementation Plan

> Agentic workers use subagent-driven-development with exclusive module ownership; root integrates and commits verified logical units, as requested.

**Goal:** Runnable end-to-end local JobOps V1 implementing `docs/product-brief.md`.
**Architecture:** Next.js modular monolith; PostgreSQL/Drizzle persistence; server-rendered lists and client forms backed by validated server actions. Local storage abstraction and deterministic services.
**Tech Stack:** Next.js stable, React, TypeScript strict, Tailwind, shadcn, PostgreSQL, Drizzle, Zod, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-09-30-jobops-design.md`

## Global constraints

- No AI APIs, no external portal automation, no email sending, no guessed answers.
- Only JobOps local files/database/services are created. Existing infrastructure is untouched.
- Credentials, uploads, databases and reports stay ignored. Frequent logical commits are authorized by the user's follow-up.
- Every important state transition is validated and audited. All exports and context routes use the same access boundary.

## Review focus

- Duplicate jobs inside one batch and repeated merge imports preserve the unique job and useful snapshots.
- PDF failures retain the file and disclose extraction status; unsafe filenames never determine storage paths.
- UNKNOWN answers stop preparation and never turn into guessed canonical answers.
- Mission results cannot claim submission without human confirmation or silently overwrite profile state.
- Ambiguous mail needs review; imports, OAuth and exports do not leak credentials or execute HTML.

## Tasks and ownership

- [x] Foundation (root): package/runtime configuration, Docker Compose, security boundary, shared action form and primitives, environment and checks. Verify npm installation and localhost server.
- [x] Data and resume domain (data worker): `src/db`, `src/services/storage`, `src/services/pdf`, `src/services/keywords`, `src/features/resumes`, resume pages/routes, migrations and seed. Tests for extraction, coverage, path safety and real upload.
- [x] Workbench and ancillary domain (workspace worker): gallery first, shell/theme, profile/contact/mail/candidate/settings UI and domain modules. Tests for unknown answers, mail rules and profile diffs; Gmail read-only boundary with import fallback.
- [x] Mission domain (mission worker): `src/features/missions`, mission pages/JSON/result/evidence, safety and context tests; transactional result updates and execution history.
- [x] Job and application domain (root): jobs/details/manual add/import/duplicate preview/merge, saved comparisons, applications/table/board/events, Today, exports. Unit tests and database integration.
- [x] Integration and verification (root + independent review): migrate/seed, production build, lint/typecheck/Vitest, Playwright important workflows, security/functional review, fix findings, README and operator documentation, leave localhost running.

## Shared interfaces

`src/db/index.ts` exports `db`; `src/db/schema.ts` exports plural camelCase tables and enum value arrays. JSON columns are typed records/arrays. `src/lib/actions.ts` exports `ActionState`, `formString`, `formJson` and `actionError`. `ActionForm` accepts `(previous: ActionState, formData: FormData) => Promise<ActionState>` and renders children/errors/pending. Common UI exports `PageHeader`, `Panel`, `EmptyState`, `StatusBadge`, `Field`, and `Button`. Each module validates all FormData and uses transactions for state/event writes.

## Ledger

Ruling: no approval gates or visual selection pause — user's newest brief directs autonomous choices. Cost if wrong: reversible visual refinement via retained gallery.
Ruling: existing repository contains the app under `jobops/`; no nested Git repository — preserves the established JOB_FINDER key and avoids detached history.

Review outcome: duplicate snapshot ordering, source validation, OAuth session continuity, concurrent mail review, consistent priorities/date preferences, and Today navigation were corrected. Final checks passed: production build, TypeScript, ESLint, Prettier, 59 unit tests, 14 Chromium flows, and zero dependency advisories. Browser tests now use their own database/server/upload root. Live Gmail remains unverified without credentials.
