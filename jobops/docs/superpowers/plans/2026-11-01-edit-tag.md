# Edit tag and the two rejection tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix a wrongly tagged email from a pencil on its row through a two-step dialog with a
snackbar and Undo, and split Rejection into Application rejected and Rejected after interview,
sorted from the user's own interview rounds.

**Architecture:** Tags stay derived from `mail_messages.classification`; a new
`INTERVIEW_REJECTION` enum value backs the second rejection tag. A pure `rejectionKind` rule runs
once per email when it is first stored (ingest and Include this) and once over stored mail at
server start. The row is restructured so a pencil button can sit beside the tag outside the row's
toggle button; the dialog and snackbar are client components wired through `CompanyTimeline`.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Drizzle ORM on PostgreSQL 17,
Tailwind 4 theme tokens, lucide-react, Vitest (node environment), Playwright.

**Spec:** `jobops/docs/superpowers/specs/2026-11-01-edit-tag-design.md`

All paths below are relative to `jobops/`; run every command from `jobops/`.

## Global Constraints

- Tag ids: `applicationRejected` ("Application rejected", `FileX`) and `interviewRejected` ("Rejected after interview", `MessageSquareX`); both use the `--tag-rejection*` colour pair and the `rejected` stage.
- `REJECTION` keeps its name and means Application rejected; the new enum value is `INTERVIEW_REJECTION`. The classifier never returns it.
- Nothing changes before the user presses **Yes, change tag**; retagging never changes attention, company, application link or outcomes.
- A tag chosen by hand always wins: sorting runs once per email and skips mail with a `MAIL_RETAGGED` log.
- Snackbar: "Tagged as {label}" with **Undo**, six seconds, paused while hovered or focused, one at a time, `role="status"`.
- Use theme tokens only (no palette literals); follow existing component idioms (`pressable`, `morph`, `reveal`, native `<dialog>` like `src/features/timeline/drawer.tsx`).
- Normal app use is Docker-only (`docker compose up -d --build` from the repo root). `npm run test:db` uses `jobops_e2e` only. `npm run test:e2e` starts a host test server on port 3211: run it only with the user's go-ahead.
- Commits: key `JOB_FINDER-9999: <summary>`, no conventional prefixes, footer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit only when the user says so; each task ends with its ready message.
- `src/app/gallery/applications-sync/` and `src/features/applications/sync-gallery/` are someone else's uncommitted work and use the `rejection` tag. Do not edit them. If Task 1 breaks their typecheck, stop and ask the user.

## Review Focus

- Pressing **Yes, change tag** twice, or retagging to the tag it already has, must save once and log once (Task 4 test `retagging to the same tag twice logs once`).
- Undo after the email vanished from view (filtered out by a tag filter, or deleted) must still work or show an error, never throw (Task 4 test `restoring an unknown email is refused`; Task 6 e2e `Undo works after the row leaves a tag filter`).
- Keyboard users: Tab reaches the pencil after the row's toggle, Enter opens the dialog, Escape closes it with nothing changed and focus back on the pencil (Task 6 e2e `keyboard: tab to the pencil, Escape cancels`).
- Placing a stored rejection email at a company with earlier rounds must not re-sort it (Task 2 test `placing a rejection email later does not re-sort it`).
- A handled email must say "stays handled", not "still needs you", in step 2 (Task 5 render test `step 2 says a handled email stays handled`).
